# DSH 消息回退

适用于 **DeepSeek Harness**（当前在 `0.2.2-rc.1` 上构建测试，不按 dsh 版本拦截加载） 的消息增强插件，用来替代 dsh-rewind-plugin 和 dsh-redo：

- **用户消息下的“回退并编辑”**：对话回到这条消息发出之前，这条消息的文字、图片和文件回到输入框，可修改后再发送。
- **用户消息下的“从此消息重新生成”**：撤回这条消息之后的对话，用原消息（含图片和文件）重新生成。
- **最新一条模型回复下的“重新生成”**：撤回这一轮回复，用这一轮的消息重新生成。

**不恢复工作区文件。** 如果要撤回的对话里修改过工作区文件，会先弹出警告，有三个按钮：

| 按钮 | 作用 |
| --- | --- |
| 取消 | 什么都不做 |
| 确认 | 照常回退或重新生成 |
| 确认并附加提示 | 照常执行，并在消息末尾加一句提示，告诉模型工作区已被修改、当前是回退或重新生成 |

“修改过”的判断来自会话日志：

- 官方 workspace-changes 记录的有文件变更的轮次（包括 bash 改动，需要 git 仓库）；
- 写入或编辑类工具（默认 `write`、`edit`）的调用。

没有修改时：

- 编辑直接执行，可撤销；
- 重新生成如果会撤回更早的多轮对话，或当前任务在运行，先简单确认一次。

## 工作方式

### 原地回退

rc.5 的会话日志只能追加。插件在会话末尾追加一条空的系统消息，用替换记录把目标消息及之后的内容从模型上下文中遮掉（官方 `/compact` 用的是同一机制），不分叉、不新建会话。

- **回退并编辑**：
  - 宿主记下目标（运行中的任务会先停止，排队消息一并丢弃）。
  - 浏览器把原文和附件放回输入框。文件附件重新上传。
  - 原消息处显示“已回退到这条消息”和“撤销回退”按钮。
  - 发送下一条消息时，插件在模型请求之前写入替换记录，新消息接在后面。
  - 不发送就不会改动会话日志；撤销即恢复原样。
- **重新生成**：宿主直接用原消息内容重新发送。图片和文件沿用已保存的附件引用，不重新上传。替换记录同样在新请求之前写入。

### 界面隐藏

官方聊天界面会继续显示被替换掉的历史，插件为此给每个打开的会话维护一份数据：

- 从会话事件流里读取回退记录，只处理每次新到的事件，不重扫全部事件；
- 生成一张只作用于该会话的样式表，按轮次（`data-chat-turn`）或单个节点（`data-chat-node-key`）隐藏被撤回的内容；
- 不监听 DOM 变化。样式表只在回退生效或加载更早历史时重建。

dsh-rewind-plugin 和 dsh-redo 以前做过的回退也会被识别并隐藏。

### 界面挂载

rc.5 的用户消息行没有可供插件追加按钮的扩展槽位。插件以更低优先级（-10）注册 `user` / `steering` 两种聊天节点渲染器：

- 每次渲染时找到当前的官方渲染器并原样渲染，再在下方加一行按钮（悬停显示，触屏设备常显）。
- 官方渲染器随 HMR 更新时自动跟随。卸载本插件即恢复官方渲染器。

最新回复下的“重新生成”使用官方的 `conversation.chat.assistant-actions` 动作槽。

**dsh-redo 也在同一位置、同一优先级注册，两者不能同时启用。** 安装本插件前先卸载 dsh-redo 和 dsh-rewind-plugin。

## 安装

从 GitHub 的预构建发布提交安装。发布提交已带构建好的 `lib/` 且去掉了 `prepare`，安装时不装 devDependencies、不构建。在 dsh「插件 → 添加插件」输入固定到完整 SHA 的来源（每个版本的 SHA 见 `release` 分支或 `v<版本>` 标签），确认安装并启用：

```text
github:forever-lwy/dsh-message-rewind#<release 提交的完整 SHA>
```

不要安装 `master`：源码分支不含 `lib/`，安装时会靠 `prepare` 拉全部 devDependencies 现场构建，很慢。dshmarket 按发布提交里 `package.json` 的版本号判断是否有更新。

包名自 0.2.2 起为 `@forever-lwy/dsh-message-rewind`。npm 与插件市场目录里已有他人发布的同名包 `dsh-message-rewind`，旧包名会被市场当成那个插件并提示“可更新”。从 0.2.1 及更早版本迁移时，先卸载旧的 `dsh-message-rewind`，再安装新包；两者注册同一个 `message-rewind` 宿主行，不能同时安装。

是否需要重启以安装界面提示为准。不要用 `link:`、目录依赖或模块路径把源码目录接入常用 profile。

## 设置

宿主行 `message-rewind`（`cordis.patch.yml` 插入的根级行）接受以下配置，修改后重启该行生效：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `mutatingTools` | `write`, `edit` | 视为修改工作区文件的工具名 |
| `attachmentMaxBytes` | 64 MiB | 回填输入框时单个附件的上限 |
| `stopTimeoutMs` | 20000 | 回退前等待运行中任务停止的最长时间 |

插件不在磁盘上保存任何数据。

## 注意

- 被压缩出上下文的消息、会话开头的消息无法回退。
- 回退只撤回对话。工作区文件、终端状态和外部副作用保持原样。
- 待发送的编辑保存在宿主内存中；宿主重启后失效，原消息重新显示。
- 撤回的内容仍保存在会话日志里，只是不再进入模型上下文，也不在界面显示。

## 开发

```sh
npm install
npm run build   # tsc + 浏览器构建 lib/client.js
npm run check
npm test
npm run release   # 本地生成 release 提交和 v<版本> 标签（不推送；正常发版由 Actions 完成）
```

发版由 GitHub Actions（`.github/workflows/release.yml`）完成：递增 `package.json` 版本并提交，推送 `master`。workflow 按 lockfile `npm ci`，发现 `v<版本>` 标签还不存在时运行 `scripts/release.mjs`：构建、测试，用临时索引生成带 `lib/`、去掉 `prepare` 的发布提交，挂在 `release` 分支上（父提交是上一个发布提交和本次源码提交）并打标签，再推送分支和标签。安装来源写在该次运行的摘要里，也可以取 `v<版本>` 标签指向的提交。版本号没变的推送只构建和测试。

`npm run release` 也可以在本地生成同样的发布提交（不推送），用于 Actions 不可用时手动发版。

测试覆盖的内容：

- **宿主**（真实 rc.5 `Session`）：
  - 检查附件和写操作；
  - 编辑的预备、撤销与替换；
  - 重新生成时原附件和提示的发送；
  - 停止任务后新出现修改时的再次确认；
  - 拒绝的情形。
- **浏览器**：
  - 回退记录的识别（含两个旧插件的记录）；
  - 隐藏样式的生成；
  - 增量读取与引用计数；
  - 编辑回填；
  - 三按钮警告的各个分支；
  - 官方渲染器包装、撤销提示、隐藏行；
  - 重新生成按钮的显示条件；
  - 槽位注册与 rc.5 优先级。
