# DSH 消息回退

适用于 **DeepSeek Harness 0.2.1-rc.5** 的消息增强插件：

- **每条用户消息下的“回退”按钮**：对话回到这条消息发出之前，工作区文件恢复到当时的状态，这条消息的文字、图片和文件重新回到输入框，可修改后再发送。
- **最新一条模型回复下的“重新生成”按钮**：撤回这一轮回复和它对文件的修改，再用原消息重新生成。

两个按钮都会先弹出确认面板，说明会恢复多少文件、是否有检查点、是否要先停止正在运行的任务。

## 工作方式

### 文件检查点

每当你发出一条消息（开启新一轮的消息，或在运行中插入的消息），插件在模型执行任何工具之前，把会话工作目录复制成一个检查点：

- 内容按 SHA-256 去重、gzip 压缩存放，未变化的文件不会重复保存；后续检查点只读取变化过的文件（大小、修改时间、inode 判定，重启后仍有效）。
- 工具执行会等待本条消息的检查点写完，因此不会有工具抢先改动文件。超过 `snapshotTimeoutMs`（默认 30 秒）仍未完成时，工具照常执行，这条消息就没有文件检查点。
- **不记录、也不改动**：`.git`、`.gitignore` 排除的路径（含各层子目录的 `.gitignore` 与 `!` 反向规则）、`node_modules` 等配置的目录名、超过 `maxFileBytes` 的文件，以及 DSH 自己的数据目录。依赖目录、构建产物因此在回退后保持原样。
- 文件数超过 `maxFiles` 时检查点标记为“不完整”：回退只还原已记录的文件，不删除任何文件。
- 只为顶层会话记录；子代理与父会话共用同一工作目录，按父会话的消息回退。

回退时恢复：被修改的文件写回原内容（原子替换并恢复权限）、新建的文件删除、被删除的文件重建、符号链接还原、之后新建且变空的目录移除。恢复之前，插件会先给当前文件状态再做一个备份检查点；如果随后分叉对话失败，会自动用这个备份撤销文件恢复。

### 对话回退

rc.5 的会话日志只能追加，不能原地截断。插件使用 dsh 自带的 **分叉（fork）**：在这条消息之前的位置切出一个新会话，标题不变；然后归档原会话（可在归档列表找回，可在设置中关闭）。

- 切点落在这条消息所在轮次开始之前，并跳过把消息送进收件箱的记录，所以新会话停在一个完整结束的轮次上。
- 如果这条消息是在上一轮运行时排队的，新会话会继承这条排队记录；插件会把它从队列中移除，避免旧消息和修改后的消息一起发出。
- 运行中插入的消息（steering）回退时切在这条消息之前，dsh 会把这一轮按“分叉”正常收尾。
- 会话的第一条消息之前没有可保留的内容，此时改为在同一工作目录、同一智能体预设下新建会话。
- 附件由宿主读出原始字节交回浏览器，重新作为草稿附件加入输入框；文件附件会重新上传。超过 `attachmentMaxBytes` 的附件不回填，确认面板会提示。

“重新生成”针对最后一轮里你发出的最后一条消息（通常就是开启这一轮的消息），流程与回退相同，回填后自动发送；有文件附件时等上传完成再发送。

### 界面挂载

rc.5 的用户消息行没有可供插件追加按钮的扩展槽位。插件以更低的优先级注册 `user` / `steering` 两种聊天节点渲染器：每次渲染时查找当前的官方渲染器并原样渲染，再在下方加一行“回退”按钮（悬停显示，触屏设备常显）。官方渲染器随 HMR 更新时自动跟随；卸载本插件即恢复官方渲染器。“重新生成”使用官方的 `conversation.chat.assistant-actions` 动作槽，只在最后一轮的收尾回复、且会话未运行时显示。

## 安装

开发源码与运行副本分离。版本包：

```text
/plugins/releases/dsh-message-rewind-0.1.0.tgz
```

在 dsh「插件 → 添加插件」输入上面的**容器路径**，确认安装并启用。是否需要重启以安装界面提示为准。不要用 `link:`、目录依赖或模块路径把源码目录接入常用 profile。

## 设置

宿主行 `message-rewind`（`cordis.patch.yml` 插入的根级行）接受以下配置，修改后重启该行生效：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 发送消息时记录文件检查点；关闭后回退只处理对话 |
| `restoreFiles` | `true` | 回退时恢复工作区文件 |
| `archiveSource` | `true` | 回退后归档原会话 |
| `maxFileBytes` | 20 MiB | 单个文件超过此大小不记录、不恢复 |
| `maxFiles` | 20000 | 每个检查点最多记录的文件数 |
| `excludeDirs` | `node_modules`, `.venv`, `venv`, `__pycache__`, `.cache`, `.next`, `.turbo` | 任意层级下排除的目录名（`.git` 始终排除） |
| `gitignore` | `true` | 遵循 `.gitignore` |
| `retentionDays` | 30 | 会话超过此天数没有新检查点时清理它的检查点和无引用数据 |
| `attachmentMaxBytes` | 64 MiB | 回填输入框时单个附件的上限 |
| `snapshotTimeoutMs` | 30000 | 单次检查点的最长耗时 |

```yaml
- id: message-rewind
  config:
    excludeDirs: [node_modules, dist, .venv]
    retentionDays: 14
```

## 数据位置

检查点保存在 `$DSH_HOME/storages/dsh-message-rewind`，本部署即宿主机 `data/.dsh/storages/dsh-message-rewind`，随 `data` 持久化与备份：

- `objects/`：去重压缩后的文件内容和检查点清单；
- `sessions/<会话>/m-<seq>.json`：每条消息的记录（分叉切点、待移除的排队消息、消息内容引用、检查点）；`backup-*.json` 为每次恢复前的文件备份；
- `lineage.json`：回退产生的新会话与原会话的对应关系，让新会话里继承来的旧消息仍能找到原会话的检查点；
- `cache/`：用于跳过未变化文件的 stat 缓存。

启动一分钟后及之后每天清理一次过期数据。

## 注意

- 文件恢复作用于整个工作目录。若其他会话同时在同一目录工作，它们的改动也会被回退到检查点时的状态。
- 插件安装之前发出的消息没有文件检查点，回退时只处理对话（确认面板会说明）。
- dsh 自带“分支”按钮产生的会话没有关联记录；在其中回退到继承来的消息时没有文件检查点。
- 回退前会先停止正在运行的任务；20 秒内未停止则放弃本次回退。

## 开发

```sh
npm install
npm run build   # tsc + 浏览器构建 lib/client.js
npm run check
npm test
```

测试覆盖：检查点的记录/恢复/忽略规则/截断/去重，基于真实 rc.5 `buildForkSeed` 的切点计算，真实 Cordis `SessionStore` 上的记录、工具等待、恢复、撤销、分叉继承与清理，客户端回退编排（停止、恢复、分叉、清队列、回填、打开、归档、重发、失败撤销），以及在 jsdom 中加载实际发布的 `lib/client.js` 验证按钮、确认面板、官方渲染器包装、重新生成按钮的显示条件和 rc.5 槽位优先级。
